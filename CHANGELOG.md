# Changelog

История версий модели и сервиса. Формат — по мотивам
[Keep a Changelog](https://keepachangelog.com/ru/1.0.0/). Для каждого заметного
решения указана мотивация: что не так было, почему выбран такой путь.

## [0.2.0] — стекинг

### Модель
- Переход с одиночного Ridge на **StackingRegressor**: 10 базовых пайплайнов
  (GB, RF, SVR, ElasticNet, BayesianRidge, XGB и др.) + RidgeCV в качестве
  мета-модели.
  - *Почему.* Ridge упирался в потолок линейной зависимости. Разные семейства
    моделей ошибаются по-разному; мета-модель учится взвешивать их предсказания,
    и ошибки частично гасят друг друга. CV RMSLE снизился с ~0.117 до **0.1157**.
  - *Как решал.* Базовые модели искал по отдельности в `research/`, замораживал
    победителей в билдер. Мета-модель — RidgeCV, чтобы не подбирать её
    регуляризацию руками и не переобучить стек на out-of-fold предсказаниях.

### Инфраструктура
- **Версионированные метрики.** `train` пишет не только `metrics.json`
  (текущая модель, читает API), но и неизменяемую копию `metrics-<версия>.json`.
  - *Почему.* Раньше при переобучении метрики предыдущей версии затирались —
    сравнить «было/стало» было нечем. Теперь история копится сама.
- **`make compare`** — таблица метрик двух последних версий с дельтой.
- **`make metrics`** — отчёт по метрикам с юникод-барами и подписью единиц
  (доллары / % / лог-единицы), без запуска обучения.
- **`make submit`** + `scripts/predict_test.py` — генерация Kaggle submission.
  - *Почему так.* У Getting Started таргет теста публичен, поэтому единственная
    честная внешняя оценка — Public LB, где ответы держит Kaggle. Локального
    holdout на «ответах» в проекте нет намеренно.
- Release-workflow больше не зависит от локальных ответов теста: release-notes
  строятся из CV RMSLE и baseline lift.

## [0.1.2] — устойчивость к «грязному» входу

- **Защитные импьютеры для полностью пустых записей.**
  - *Почему.* В проде запрос может прийти без большинства полей. Пайплайн должен
    предсказать, а не упасть. Пропуски заполняются медианами/«отсутствием».
- **Неизвестные категории кодируются как sentinel, а не NaN.**
  - *Почему.* Категория, которой не было в обучении (например, редкий тип
    района), раньше проваливалась в NaN и ломала downstream-шаги. Sentinel —
    явное «неизвестно», устойчивое к незнакомым значениям.

## [0.1.1] — NaN-устойчивый препроцессинг

- Препроцессинг из ноутбука перенесён в пакет с корректной обработкой NaN
  на каждом шаге per-column `ColumnTransformer`.
  - *Почему.* Прямой перенос из ноутбука ронял пайплайн на реальных пропусках
    Kaggle-теста (дома без подвала/гаража). Разложил обработку по колонкам.

## [0.1.0] — первый рабочий конвейер

- FastAPI-сервис: `/health`, `/predict`, контракт `model_version`, схема входа
  на 80 полей с алиасами Kaggle.
- Training CLI: артефакты (joblib + input_schema + manifest) и метрический гейт.
- Fail-fast загрузчик модели: сервис не стартует при рассогласовании версий
  окружения с теми, на которых обучалась модель.
- CI: линт + тесты с кэшем Kaggle-датасета; отдельные workflow на релиз модели
  (`model-v*`) и сборку multi-arch Docker-образа в ghcr (`api-v*`).

### Ключевое решение этой версии
- **Отказ от фильтра выбросов по площади.** Пробовал отсекать крупные дома
  (`GrLivArea`), но на кросс-валидации это стабильно ухудшало метрику: модель
  теряла сигнал на дорогом сегменте. Оставил данные как есть — CV честнее
  ручной чистки под целевую цифру.
